# Knowledge data

This directory owns authored content for `@liuyao/knowledge`. Records declare `schemaVersion`; build-time dispatch validates V1 with `../schema/record.schema.json` and V2 with `../schema/record-v2.schema.json`. The V1 schema path and authored V1 files remain unchanged. See the [knowledge model](../../../docs/design-docs/knowledge-model.md) for the approved contracts and implementation limits.

## File map

| Path                                 | Owns                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------ |
| `manifest.json`                      | File inventory, topics, release IDs, and the next content batch          |
| `sources.json`                       | Supplied works, edition fingerprints, bibliographic metadata, and rights |
| `citations/`                         | Edition-specific passage locations and textual layers                    |
| `trigrams/`                          | Eight reviewed entities and structural evidence                          |
| `hexagrams/`                         | Reviewed quẻ, six line positions, and separate special passages          |
| `casting/`                           | Casting rules and worked examples                                        |
| `liuyao/`                            | Foundational rules, structured tables, and attributed advanced articles  |
| `terms/`                             | Reviewed definitions and aliases                                         |
| `legacy/catalog.json`                | Unmigrated compatibility content with an explicit `unaudited` status     |
| `*.ts`                               | Compatibility exports from the JSON adapter                              |
| `facts.ts`                           | Project-owned associations between result fields and rule IDs            |
| `../schema/record.schema.json`       | Unchanged V1 record schema                                               |
| `../schema/record-v2.schema.json`    | Strict V2 authored-record schema                                         |
| `../src/book-migration.ts`           | Pure upcast for prevalidated V1 records; no schema validation            |
| `../src/book-release.generated.json` | Generated, sanitized public snapshot; never author by hand               |
| `../src/book-data.generated.ts`      | Typed wrapper for the generated snapshot                                 |
| `../src/book-catalog.ts`             | Public list/get APIs over versioned records and released sources         |
| `../src/book-snapshot.ts`            | Public snapshot identity format and parser                               |

Edit JSON for migrated content. Do not author equivalent records in TypeScript or the legacy snapshot.
The snapshot preserves existing content without granting supplied-book review status.
`../src/book-release.generated.json` is generated by corpus validation and contains selected released records, reachable citations, referenced editions, sanitized source metadata, projected topics, used project evidence metadata, and the snapshot identity. It is stored under `src/`, outside this authored-data tree. Edition `localInputPath` values and PDFs are not projected. The current projection has an empty `projectContracts` list; there are no released V2 project conventions.
`../src/book-data.generated.ts` is the generated typed wrapper for the release JSON; it does not import authored records or the raw manifest. `src/book-catalog.ts` exposes versioned records as `BookRecordVersioned` (`BookRecordV1 | BookRecordV2`) and sources as `ReleasedBookSource`, which omits local input paths. Authored source data uses the distinct `AuthoredBookSource` type.
`src/book-migration.ts` provides a pure deep-copy upcast for prevalidated V1 records. It is not a replacement for build-time schema validation. Keep existing V1 JSON records and their IDs unchanged.
`../reports/coverage.json` records remaining quẻ, line commentary by author, and topic gaps.

## Authoring workflow

1. Locate the passage in the fingerprinted supplied edition.
2. Inspect the full passage and render symbols or tables.
3. Write an original Vietnamese summary with claim-specific citation IDs.
4. Preserve interpretation attribution, necessary conditions, and discrepancy evidence.
5. Add the canonical record path to `manifest.json`.
6. After source review, record review evidence and select the ID for release.
7. Run `pnpm --filter @liuyao/knowledge validate:corpus --check-books`.
8. Run `./init.sh`.

Build and type-check commands validate the corpus and refresh generated outputs. `pnpm --filter @liuyao/knowledge validate:corpus --check` detects stale generated outputs without rewriting them; freshness covers the release JSON and typed wrapper. `--check-books` also verifies supplied-edition fingerprints.
Mechanical validation does not certify source meaning.

V2 `sourceUnitIds` refer to IDs inventoried in the [source inventory](../../../docs/reviews/knowledge/source-inventory.md). This feature validates their non-empty string shape but does not create a source-unit registry or verify ownership. Reusing a source-unit reference is allowed. Project-contract document and heading checks establish structural matches only; they do not prove acceptance. No V2 records or independent specialist/audit certification are implied by the generated snapshot.
