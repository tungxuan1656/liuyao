# Knowledge corrections

The [quality contract](../../product-specs/knowledge-quality.md#corrections-and-coverage) owns correction requirements.

Edit the canonical explanation and its book/page reference together.
Check the changed passage and direct uses. Run structural validation and relevant package checks.
Record a material remaining gap in the owning record or feature.
Git stores the previous content and the reason for the correction.

The former decision-revision and certification workflow is retired by the [simplified model](../../design-docs/knowledge-model.md#migration-history).
Do not append hash snapshots or reopen unrelated explanations.
